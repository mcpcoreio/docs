## What is a tool?

A **tool** is the fundamental unit of work in MCPCore. It has:

- A **name**: how the AI client identifies and calls it (e.g. `fetch_repo_stats`)
- A **description**: a plain-language explanation of what the tool does; the AI uses this to decide when to call it
- **Parameters**: the typed inputs the AI passes at call time
- **Logic**: JavaScript code or a no-code [workflow](/tools/workflows/overview) that runs when the tool is invoked

When the AI connects to your server, it receives the full list of tools with their schemas. It then decides autonomously which tools to call, in what order, and with what parameters.

---

## Code or workflow?

When you click **Create New Tool**, MCPCore asks how you want to build it:

| Option               | Best for                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------ |
| **Write code**       | Full control. JavaScript in a VS Code-style editor, with ready-made snippets and AI help.  |
| **Build a workflow** | No code. Connect ready-made steps like Database, Query, HTTP Request, Transform and Return. |
| **Import from OpenAPI** | You already have an API with an OpenAPI or Swagger document. Each endpoint becomes a workflow tool. See [Import from OpenAPI](/tools/import-openapi). |

Both produce the same kind of tool: AI clients see no difference. A tool always reopens in the editor it was built with. To build without code, follow the [workflow builder guide](/tools/workflows/overview). The steps below cover the code editor.

## Create a tool

<Steps>
  <Step title="Open the Tools section">
    On the server detail page, click **Create New Tool** in the **Tools** section, then choose **Write code**.
  </Step>
  <Step title="Name your tool">
    Choose a clear, descriptive name in **lowercase snake_case**:

    | Good                 | Avoid              |
    | -------------------- | ------------------ |
    | `fetch_user_orders`  | `FetchUserOrders`  |
    | `send_slack_message` | `sendSlackMessage` |
    | `query_inventory_db` | `tool1`            |

    The name appears in the MCP schema and in your analytics dashboard. It cannot contain spaces or special characters.
  </Step>
  <Step title="Write a description">
    The description is critically important: it's what the AI reads to decide when to call your tool. Be specific.

    **Good description:**

    > Fetches the number of stars, forks, and primary language for a GitHub repository. Use when the user asks about repository statistics or open-source project metrics.

    **Weak description:**

    > Gets GitHub data.
  </Step>
  <Step title="Add parameters">
    Define the inputs your code will receive via `params.*`. See [Parameters](/tools/parameters) for the full schema reference.
  </Step>
  <Step title="Set the behavior (optional)">
    Under **Behavior**, tell AI clients what the tool does to your data. See [Behavior](#behavior) below.
  </Step>
  <Step title="Write the code">
    Write JavaScript in the [code editor](/tools/editor). The sandbox gives you access to `sdk`, `params`, `env`, and `console`. See [Sandbox](/tools/sandbox) for the complete API.

    Use the **Snippets** panel to insert ready-made blocks for HTTP calls, database queries and secrets, or let the **AI Tool Builder** generate the code, see below.
  </Step>
  <Step title="Save">
    Click **Create**. The tool is live immediately on your server's endpoint. Later edits are saved with **Save & publish** or **Save draft**, and every save is kept in the [version history](/tools/versions).
  </Step>
</Steps>

## Behavior

The **Behavior** field tells AI clients what a tool does to your data. MCPCore sends it with the tool as standard MCP tool annotations. Clients such as Claude, Cursor and VS Code use it to decide whether to ask the user before running the tool.

| Behavior                       | Use it for                                          | Sent to AI clients                                 |
| ------------------------------ | --------------------------------------------------- | -------------------------------------------------- |
| **Not specified** (default)    | Tools created before this field existed             | Nothing. Each client uses its own default          |
| **Read-only**                  | Lookups, searches, reports                          | `readOnlyHint: true`                               |
| **Changes data**               | Creating or updating records, sending messages      | `readOnlyHint: false`, `destructiveHint: false`    |
| **Deletes or overwrites data** | Deleting records, replacing files, bulk updates     | `readOnlyHint: false`, `destructiveHint: true`     |

- The [Playground](/tools/playground) turns tools marked **Deletes or overwrites data** off until you allow them.
- [Imported](/tools/import-openapi) tools get a behavior from their HTTP method: GET is **Read-only**, DELETE is **Deletes or overwrites data**, and the rest **Changes data**.
- The behavior is part of every [version](/tools/versions) of the tool.

<Warning>
  The behavior is a hint for AI clients, not a permission. It does not stop the tool from writing data. Protect write tools with the [security mode](/servers/security-overview) of the server and with database users that only have the rights they need.
</Warning>

## AI Tool Builder

The **AI Tool Builder** lets you create tools by describing what you want in plain language. Instead of writing code manually, you describe the tool's purpose and MCPCore's AI generates the complete tool, including the name, parameters, and code.

### How it works

1. Open the tool editor and locate the **AI Assistant** panel on the right side
2. Type a description of what your tool should do (up to 2000 characters)
3. Click **Generate**
4. The AI produces:
   - A properly formatted `snake_case` tool name
   - Typed parameters with descriptions
   - Complete, working JavaScript code using `sdk.http()`, `sdk.db()`, or `sdk.lodash`
5. Review the generated code, make any adjustments, and save

### Example prompts

Try these to get started:

- `Fetch user profile from a PostgreSQL database using an email parameter`
- `Call a REST API endpoint and transform the JSON response`
- `Connect to MySQL, query a table with filters, and return paginated results`

### Generation limits

AI generation is available on supported plans. Each user can generate up to **20 tools per day**.

<Note>
  The AI Tool Builder uses Claude Sonnet 4 to generate code. Always review the generated code before saving, especially when the tool writes data or interacts with sensitive systems.
</Note>

## A minimal tool

```javascript
// params.repo is a string like "anthropics/anthropic-sdk-python"
const res = await sdk.http({
  method: "GET",
  url: `https://api.github.com/repos/${params.repo}`,
  headers: {
    Authorization: `Bearer ${env.GITHUB_TOKEN}`,
  },
});

const data = JSON.parse(res.body());

return {
  stars:    data.stargazers_count,
  forks:    data.forks_count,
  language: data.language,
};
```

`sdk.http()` makes an HTTP request. `env.GITHUB_TOKEN` is a secret stored in the dashboard. `params.repo` is the value the AI passed at call time. The object you `return` is what the AI receives as the tool result.
