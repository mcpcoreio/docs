## Overview

Your tool code runs in an isolated V8 runtime with a 64 MB memory limit. There is no file system access, no `require()`, no `import`, and no access to the Node.js standard library. Instead, MCPCore injects a curated set of globals:

| Global | What it is |
|---|---|
| `sdk` | Built-in helpers: HTTP client, database client, Lodash |
| `params` | The input parameters the AI passed at call time |
| `env` | Your encrypted server secrets, accessible by name |
| `headers` | Headers of the incoming MCP request. `Cookie` and `X-Api-Key` are removed, along with proxy and client IP headers. `Authorization` is passed through, so tool code can read it |
| `console` | Log output shown in the Run panel during test runs |

## `sdk.http()`: HTTP requests

Make outbound HTTP requests to any external API or service. Each HTTP request has a 10-second timeout and a 10 MB response size limit, with a maximum of 5 redirects.

```javascript
const res = await sdk.http({
  method:  "GET",           // "GET" | "POST" | "PUT" | "PATCH" | "DELETE"
  url:     "https://...",   // Full URL. Use template literals with params.*
  headers: { },             // Key-value header object
  body:    "...",           // String body for POST/PUT/PATCH
});
```

### Response methods

```javascript
res.status            // HTTP status code (number)  e.g. 200
res.ok                // true when the status is 2xx
res.headers           // Response headers as an object
res.json()            // Response body parsed as JSON
res.body()            // Response body as a raw string
```

### Example: GET with auth

```javascript
const res = await sdk.http({
  method: "GET",
  url: `https://api.github.com/repos/${params.owner}/${params.repo}`,
  headers: {
    Authorization: `Bearer ${env.GITHUB_TOKEN}`,
    "User-Agent":  "MCPCore-Tool/1.0",
  },
});

if (res.status !== 200) {
  throw new Error(`GitHub API error: ${res.status}`);
}

return res.json();
```

### Example: POST with JSON body

```javascript
const res = await sdk.http({
  method:  "POST",
  url:     "https://api.sendgrid.com/v3/mail/send",
  headers: {
    Authorization:  `Bearer ${env.SENDGRID_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    personalizations: [{ to: [{ email: params.to }] }],
    from:    { email: "noreply@yourapp.com" },
    subject: params.subject,
    content: [{ type: "text/plain", value: params.body }],
  }),
});

return { status: res.status };
```

## `sdk.db()`: Database queries

Connect to a relational database and run queries. `sdk.db()` is powered by **[Knex.js](https://knexjs.org)** under the hood, a battle-tested SQL query builder for Node.js. If you're familiar with Knex, the API will feel natural. MCPCore wraps it with a simplified interface for the most common operations.

```javascript
const db = await sdk.db({
  type:       "pg",          // "pg" | "mysql2" | "mssql"
  connection: {
    host:     env.DB_HOST,
    port:     Number(env.DB_PORT),
    database: env.DB_NAME,
    user:     env.DB_USER,
    password: env.DB_PASSWORD,
  },
});
```

<Note>
  Always store connection credentials as secrets and reference them as `env.*`. Never hardcode passwords in tool code.
</Note>

### `db.select(table, where?)`

Fetch rows from a table, optionally filtered by column values.

```javascript
// All rows
const allUsers = await db.select("users");

// Filtered rows
const pendingOrders = await db.select("orders", {
  user_id: params.userId,
  status:  "pending",
});

return { count: pendingOrders.length, orders: pendingOrders };
```

### Writing data

Use `db.query()` for inserts, updates and deletes. On PostgreSQL, add `RETURNING *` to get the affected rows back.

```javascript
const [record] = await db.query(
  "INSERT INTO events (user_id, event_type, created_at) VALUES (?, ?, ?) RETURNING *",
  [params.userId, params.type, new Date().toISOString()]
);

return { id: record.id };
```

```javascript
const updated = await db.query(
  "UPDATE subscriptions SET status = ?, cancelled_at = ? WHERE id = ? RETURNING id",
  ["cancelled", new Date().toISOString(), params.subscriptionId]
);

return { affected: updated.length };
```

### `db.destroy()`

Connections are closed automatically when the tool finishes. Call `await db.destroy()` to close one earlier.

### `db.query(sql, values?)`

Run a parameterised SQL query. Use `?` placeholders and pass values in the same order. The result is an array of rows.

```javascript
const result = await db.query(
  "SELECT product_id, SUM(quantity) as total FROM order_items WHERE created_at > ? GROUP BY product_id ORDER BY total DESC LIMIT 10",
  [params.since]
);

return { topProducts: result };
```

<Warning>
  Always use `?` placeholders when embedding user input in SQL. Never concatenate `params.*` values directly into a SQL string.
</Warning>

## `sdk.lodash`: Utility functions

A subset of [Lodash](https://lodash.com) is available for data manipulation.

```javascript
const _ = sdk.lodash;

const grouped = _.groupBy(rows, "category");
const sorted  = _.orderBy(rows, ["created_at"], ["desc"]);
const top5    = _.take(sorted, 5);
const unique  = _.uniqBy(rows, "user_id");
const flat    = _.flatMap(groups, group => group.items);
```

## `sdk.sleep()`: Wait before trying again

Pauses the tool for a number of milliseconds, for example before retrying a rate-limited request. One call waits at most 2,000 ms; longer values are cut to 2,000 ms.

```javascript
let res = await sdk.http({method: "GET", url: "https://api.example.com/report"});

if (res.status === 429) {
  await sdk.sleep(1000);
  res = await sdk.http({method: "GET", url: "https://api.example.com/report"});
}

return JSON.parse(res.body());
```

The total run time of the tool still counts toward the execution timeout. Workflow tools use the same function for their [retries](/tools/workflows/nodes#retries).

## `params`: Tool inputs

`params` is a plain object containing the values the AI passed when calling the tool. The keys are the parameter names you defined in the tool schema.

```javascript
// If you defined a parameter named "userId" of type "string":
const id = params.userId;

// If you defined "limit" of type "number" with default 10:
const limit = params.limit ?? 10;

// If you defined "filters" of type "object":
const { status, category } = params.filters;
```

Parameters are validated against the schema you defined before the code runs. If a required parameter is missing or has the wrong type, the tool returns a schema error without executing your code.

## `env`: Secrets

`env` contains the encrypted secrets you stored in the server's **Secrets** tab. Reference them by their key name:

```javascript
const token    = env.GITHUB_TOKEN;
const password = env.DB_PASSWORD;
const apiKey   = env.OPENAI_API_KEY;
```

`env` is read-only. Values are strings. See [Secrets](/tools/secrets) for how to create and manage them.

## `console`: Structured logging

Log messages from your tool code. During a test run, the output appears in the Run panel's **Logs** section. During live calls, it isn't shown in the dashboard or in [Traffic Logs](/observability/traffic-logs): it goes to MCPCore's server logs, where exact secret values of 6 characters or more are masked. Shorter or encoded values aren't, so never log secret values. To see something in Traffic Logs, include it in the tool's response.

```javascript
console.log("Processing request for user:", params.userId);
console.log("Fetched", rows.length, "rows from database");
console.warn("Rate limit approaching:", remaining, "requests left");
console.error("Database query failed:", error.message);
console.log("Response status:", res.status);
```

| Method | Log level | When to use |
|---|---|---|
| `console.log` | INFO | General progress messages |
| `console.warn` | WARN | Recoverable issues, degraded operation |
| `console.error` | ERROR | Failures that affect the result |

<Note>
  During live calls, a tool run can write up to 100 lines of up to 2,000 characters each. For large payloads, log a summary rather than the full object.
</Note>

## Error handling

Throw an error to signal a failure to the AI:

```javascript
const res = await sdk.http({ method: "GET", url: `...` });

if (res.status === 404) {
  throw new Error(`Repository not found: ${params.repo}`);
}

if (res.status !== 200) {
  throw new Error(`Upstream API returned ${res.status}: ${res.body()}`);
}
```

Uncaught errors are captured, logged with the full stack trace, and returned to the AI as a tool error. The request is recorded in [Error Logs](/observability/error-logs).
