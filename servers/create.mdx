## What is an MCP server?

An MCP server is a named, hosted process that exposes one or more tools to any MCP-compatible AI client. When the AI connects to your server, it discovers all available tools and their input schemas, then decides which ones to call based on the conversation.

Each server gets its own:

- **Subdomain URL**: `https://your-subdomain.mcpcore.io/mcp` (chosen by you at creation time)
- **Custom domain**: optionally use your own domain with automatic SSL
- **Security mode**: independent auth configuration (Public, API Key, OAuth 2.0, or Bearer Token)
- **Tool collection**: the functions the AI can call
- **Environment secrets**: encrypted key-value pairs referenced as `env.KEY_NAME`

You can create as many servers as you need. Common patterns:

| Pattern                    | Example subdomain                         |
| -------------------------- | ----------------------------------------- |
| One server per project     | `github-tools`, `jira-tools`, `slack-bot` |
| One server per environment | `my-api-dev`, `my-api-prod`               |
| One server per team        | `data-team`, `infra-tools`                |
| One server per customer    | `acme-corp`, `example-inc`                |

## Create a server

Servers are created with a short, five-step wizard. Each step only validates its own fields, so you always know what is missing before you move on. The server code, instructions and transport are set up for you automatically.

<Steps>
  <Step title="Open the wizard">
    From the dashboard sidebar, click **My Servers**, then click **Create Server**. If you don't have a server yet, the dashboard shows a **Create your first MCP server** button that opens the same wizard.
  </Step>
  <Step title="Basics: name your server">
    ### Title

    A human-readable name displayed in the dashboard (max 100 characters).

    > Example: `GitHub Tools`, `Slack Bot`, `Inventory API`

    ### Description _(optional)_

    A short description of what this server does (max 255 characters).
  </Step>
  <Step title="Category: what it does">
    Pick the card that best describes your server's purpose:

    | Category                  | Use for                                           |
    | ------------------------- | ------------------------------------------------- |
    | Data & Database           | Database connections, SQL, NoSQL, data warehouses |
    | Files & Documents         | File systems, cloud storage, document management  |
    | Web & Search              | Web scraping, search engines, external APIs       |
    | DevTools & Repositories   | Git, version control, CI/CD, code hosting         |
    | Messaging & Collaboration | Slack, Teams, email, communication platforms      |
    | Business & Productivity   | CRM, ERP, project management, analytics           |
    | AI & ML Services          | Machine learning APIs, AI models, NLP services    |
    | Automation & Workflows    | Zapier, workflow engines, task automation         |
    | Security & Auth           | Authentication, authorization, security tools     |
    | Custom & Internal         | Internal tools, custom integrations               |
    | Other                     | Uncategorized or specialized services             |
  </Step>
  <Step title="Domain: where it lives">
    ### Subdomain

    The subdomain for your server's endpoint (1–63 characters). Only lowercase letters, numbers, and hyphens; it cannot start or end with a hyphen. A live preview shows the final URL while you type.

    > Example: `github-tools` → `https://github-tools.mcpcore.io/mcp`

    <Warning>
      Subdomains must be globally unique across all MCPCore accounts. If your preferred subdomain is taken, try adding a suffix (e.g. `my-github-tools`).
    </Warning>

    ### Custom domain _(optional)_

    Skip this if you are not sure, you can add it later. To use your own domain (e.g. `mcp.yourcompany.com`), add a CNAME record pointing to `proxy.mcpcore.io`, then click **Verify CNAME**. SSL is provisioned automatically.

    <Note>
      Custom domains are available on paid plans. MCPCore monitors SSL certificate status and performs periodic verification.
    </Note>
  </Step>
  <Step title="Security: who can access">
    Choose how incoming requests are authenticated. The form only shows the field the selected mode needs:

    | Mode      | What you fill in                                                       |
    | --------- | ---------------------------------------------------------------------- |
    | Public    | Nothing, anyone with the URL can connect                               |
    | Unlisted  | A secret key (32–100 characters) that becomes part of the endpoint URL |
    | API Key   | An API key that clients send in the `X-API-Key` header                 |
    | OAuth 2.0 | The metadata URL of your OAuth authorization server                    |

    For OAuth 2.0, MCPCore checks the authorization server's metadata before you continue. Don't have an OAuth server yet? Start from the [OAuth example server](/servers/security/oauth-example).

    Open **Advanced** to set the **Rate limit per minute** (0 = unlimited, max 5000, default 60). See [Security Overview](/servers/security-overview) for a full comparison of the modes.
  </Step>
  <Step title="Review: confirm and create">
    Check the summary and click **Create**. You can go back to any step without losing what you entered.
  </Step>
</Steps>

### After the server is created

The wizard ends on a **Your MCP server is ready** screen with your endpoint URL. From there:

- **Create your first tool** opens a dialog where you choose between [writing code](/tools/create) and [building a workflow](/tools/workflows/overview).
- **Skip for now** takes you to the server detail page.

<Tip>
  New accounts get a short guided tour on the dashboard, the server detail page and both tool editors. Each tour is shown once and can be skipped at any time.
</Tip>

## The server detail page

Once created, the server detail page is your central hub. The page is organised into tabs:

| Tab             | What's here                                                                             |
| --------------- | --------------------------------------------------------------------------------------- |
| **Overview**    | Subdomain URL, security info, tools list, environment secrets, recent logs and traffic |
| **Analytics**   | Request volume, error rate, latency, tool breakdown, session and hourly trends         |
| **Integration** | Ready-to-paste configs for Codex, Claude Desktop, Cursor, VS Code, Windsurf, and Cline |

The tools list shows how many tools are active and inactive, and you can filter it with the **All / Active / Inactive** switch. Each tool opens in the editor it was built with: the code editor or the workflow builder.

---

## Your server's endpoint URL

Your server's MCP endpoint URL is based on the subdomain you chose:

```
https://your-subdomain.mcpcore.io/mcp
```

If you configured a **custom domain**:

```
https://mcp.yourcompany.com/mcp
```

Copy the endpoint URL from the **Overview** section of the server detail page. This URL is permanent, it never changes if you rename the server or update its settings.
